# Claude Code 要約（コンパクション）検証キット

会話が長くなると、Claude Code は古いやり取りを要約に置き換えます。このキットでは、要約のあとに何が残り、何が消えるのかを、公式ドキュメントの記述どおりか手元で確かめます。

- 参照ドキュメント: https://code.claude.com/docs/en/context-window#what-survives-compaction
- 所要時間: 20分ほど（4つの検証。それぞれ新しいセッションで行います）
- 必要なもの: Claude Code、git、ターミナル（macOS または Linux）
- 少しですがトークンを使います

| 検証 | 確かめること |
|---|---|
| 1 | CLAUDE.md を途中で書き換えたとき、要約のあとも最新の内容が効いているか |
| 2 | 読んだファイルは、要約のあと更新日時の新しい順に5つまで戻るか。大きいファイルは名前だけになるか |
| 3 | `paths:` 付きのルールは要約で消え、対象ファイルを触ると戻るか |
| 4 | 要約の直後に動くよう設定したフックは、本当に動くか |

## はじめに読むこと

### Claude に任せず、人が手で進める

「README どおりに検証して」と Claude に頼んでもできません。clone も README を読むのも人が行い、Claude には手順にある文だけを入力してください。

<details>
<summary>理由</summary>

- `/compact`（要約）やセッションの起動し直しは、人にしかできません。
- 記録する `Read ...` や `Loaded ...` の行はターミナルの表示で、Claude 自身には見えません。
- この README には合言葉や予想される結果が書いてあります。Claude が読むと答えを先に知ってしまい、検証になりません。

</details>

### 表記の約束

| 表記 | 意味 |
|---|---|
| **ターミナル:** | ターミナルで打つコマンド |
| **Claude に入力:** | Claude Code の入力欄に打つもの。かぎかっこの中の文は、そのまま入力する |
| **見る:** | 画面で確かめること |
| **記録【1A】** | 結果テンプレートの、同じ見出しの欄に書く |

### 言葉の意味

- **要約**: 会話を短くまとめて置き換えること。`/compact` で起こせます（公式には「コンパクション」）。
- **Read ツール**: Claude がファイルを読むときの標準の道具。`cat` コマンドなど別の方法で読むと、要約のあとに戻るファイルとして数えられず、結果が変わります。そのため手順では「Read ツールで」と指定しています。
- **フック**: 決まったタイミングで自動的に動くよう、設定ファイルに書いておくコマンド。

## 準備（最初に1回だけ）

1. **ターミナル:** 次を打ちます。

   ```bash
   git clone https://github.com/cookkawasaki/claude-compact-check
   cd claude-compact-check
   ```

2. `result-template.txt` の中身を、メモアプリやエディタにコピーします。結果はそこに書いていきます（リポジトリの中には保存しないでください）。
3. **ターミナル:** `claude --version` → 記録【環境】
4. **ターミナル:** `ls ~/.claude/CLAUDE.md` → ファイル名が出たら「ある」、`No such file or directory` と出たら「ない」 → 記録【環境】
   - 自分で作った覚えがなくても、あることがあります。必ず打って確かめてください。
   - 会社が配っている Claude Code の設定があるかも、分かる範囲で記録【環境】に書きます。分からなければ「分からない」で構いません。
5. モデルは Sonnet を勧めます（Claude Code の中で `/model` を打って切り替え）。エフォート（考える量）の設定があれば、低め〜標準で十分です。
6. 初めて `claude` を起動すると、このフォルダを信頼するか聞かれます。許可してください（検証4のフックを動かすため）。

## 共通の約束

- **検証ごとに Claude Code を起動し直します。** 終わったら `/exit` で閉じ、次の検証は `claude` から始めます。前の検証の内容が混ざらないようにするためです。
- `/compact` を打って「要約するほどの会話がない」という趣旨の表示が出たら、適当にもう1〜2往復話してから打ち直してください。
- 検証の合間に **ターミナル:** `git status` を打ち、`nothing to commit, working tree clean` と出るか確かめます。変更されたファイルが出たら、`git restore .` で戻してから次へ進みます。

## 検証1　CLAUDE.md を書き換えたとき、要約のあとも最新の内容が効いているか

**ねらい:** このフォルダの `CLAUDE.md` には「返事の最後の行に ★ を書く」とあります。途中でこれを ◆ に書き換え、要約の前後でどちらが付くかを見ます。

1. **ターミナル:** `claude`
2. **Claude に入力:** 「自己紹介を一文でしてください」
   - **見る:** 返事の最後の記号 → 記録【1A】
   - ★ が付かなければ、検証1はここで終えます（理由は下の補足）。
3. **ターミナル:** Claude Code は開いたまま、もう1つターミナルを開き、`claude-compact-check` フォルダに移動して次を打ちます（エディタで ★ を ◆ に書き換えても構いません）。

   ```bash
   perl -pi -e 's/★/◆/g' CLAUDE.md
   ```

4. **Claude に入力:** 「好きな季節を一文で教えてください」
   - **見る:** 返事の最後の記号 → 記録【1B】
5. **Claude に入力:** `/compact`
   - 要約が終わるまで待ちます。「要約するほどの会話がない」と出たら、1〜2往復話してから打ち直します。
6. **Claude に入力:** 「好きな果物を一文で教えてください」
   - **見る:** 返事の最後の記号 → 記録【1C】
7. **Claude に入力:** 「ファイルを読まずに答えてください。いまの CLAUDE.md は、返事の最後の行にどの記号を書くよう指示していますか」
   - **見る:** 答えの記号 → 記録【1D】
8. **Claude に入力:** `/exit`
   - **ターミナル:** `git restore CLAUDE.md`（★ に戻す）

**予想**

- 【1A】★
- 【1B】◆（2.1.317 で試したときの結果）
- 【1C】◆
- 【1D】◆

<details>
<summary>予想と違ったとき・なぜそうなるか</summary>

- **【1A】で ★ が付かない:** 個人の設定などが邪魔している可能性があります。テンプレートの「気づいたこと」にそう書いてください。
- **【1B】が ◆ になる理由:** Claude Code は、読み込んだファイル（CLAUDE.md を含む）の更新日時を毎ターン確かめ、書き換わっていれば差分を「changed on disk」というお知らせとして Claude に渡します。そのため検証1では、【1C】の ◆ が「要約で読み直されたから」なのか「このお知らせで届いたから」なのかは区別できません。【1B】が ★ だった場合も、そのまま記録してください。
- **【1C】が ★ で【1D】が ◆:** 要約の文章に「★ を付ける」が書き残されたためです。【1D】が ◆ なら、最新の CLAUDE.md は効いています。

</details>

## 検証2　読んだファイルは、更新日時の新しい順に5つまで戻るか

**ねらい:** `files/` には、小さいファイル6つ（`small1.txt`〜`small6.txt`）と大きいファイル1つ（`big.txt`、約1万トークン）があります。ドキュメントには「更新日時の新しいものから5つ戻る」とあります。読ませる順番と更新日時の順番をわざと逆にして、どちらの順で選ばれるかを見ます。

1. **ターミナル:** Claude Code を起動する**前に**、次を打って更新日時をそろえます（small1 がいちばん新しく、small6 がいちばん古くなります）。

   ```bash
   touch -t 202601010106 files/small1.txt
   touch -t 202601010105 files/small2.txt
   touch -t 202601010104 files/small3.txt
   touch -t 202601010103 files/small4.txt
   touch -t 202601010102 files/big.txt
   touch -t 202601010101 files/small5.txt
   touch -t 202601010100 files/small6.txt
   ```

   打ったら、テンプレートの検証2「touch を打ったか」に記録します。

2. **ターミナル:** `claude`
3. **Claude に入力:** 「Read ツールで files/small1.txt と files/small2.txt を読んで、それぞれの合言葉を答えてください」
4. **Claude に入力:** 「Read ツールで files/small3.txt から files/small6.txt までの4つを読んで、それぞれの合言葉を答えてください」
5. **Claude に入力:** 「Read ツールで files/big.txt を最初から最後まで読んで、最初の行と最後の行を答えてください」
6. **Claude に入力:** `/compact`
   - 要約が終わるまで待ちます。「要約するほどの会話がない」と出たら、1〜2往復話してから打ち直します。
7. **見る:** `Compacted` の行の下に並ぶ行を、そのまま貼る → 記録【2A】

   ```
   ⎿  Compacted (ctrl+o to see full summary)
      Read files/small1.txt (2 lines)
      Read files/small2.txt (2 lines)
      （…ほかの Read 行が続く…）
      Referenced file files/big.txt
   ```

   `Read` は中身ごと戻ったファイル、`Referenced file` は大きすぎて名前だけ戻ったファイルです。1行も出なければ「表示なし」と書きます。

8. **Claude に入力:** 「ファイルを読まずに答えてください。いま中身が分かるファイルと、名前しか分からないファイルを挙げてください」
   - **見る:** 返事をそのまま貼る → 記録【2B】
9. **Claude に入力:** `/exit`
   - テンプレートの残りの欄（big.txt を Read ツールで読んだか、手順以外に Claude が読んだファイル）も記録します。

**予想**

- 【2A】`Read` は small1〜small4 の4行、`Referenced file` は `files/big.txt`。small5 と small6 は出てこない
- 【2B】small5・small6 の合言葉も答えられることがある

<details>
<summary>予想と違ったとき・なぜそうなるか</summary>

- **`Read` が4つしかない:** 「5つまで」のうち1枠を big.txt が使うためで、予想どおりです。
- **`Read` が small3〜small6 になった:** 更新日時ではなく「読んだ順」で選ばれています。ドキュメントと違う結果なので、そのまま記録してください。
- **【2B】で small5・small6 を答えられる:** ファイルとしては戻らなくても、要約の文章に合言葉が書き残されるためです。
- **Claude が `head` や `tail` などで big.txt を見た／手順以外のファイル（README など）を自分から読んだ:** 戻るファイルの数え方が変わります。テンプレートの該当欄に書いてください。

</details>

## 検証3　`paths:` 付きのルールは要約で消え、また戻るか

**ねらい:** `.claude/rules/api.md` には、`api/` のファイルを触るときだけ読み込まれるルール「返事の最初に【API】と書く」があります。読み込まれると、画面に `Loaded .claude/rules/api.md` という行が出ます。
ルールのファイル自体も「要約のあとに戻る5つ」に入ることがあるので、ルールのファイルを古い日付にし、新しいファイルを後から6つ読ませて、5つから外します。

1. **ターミナル:** Claude Code を起動する**前に**、次を打ちます。

   ```bash
   touch -t 202501010000 api/sample.ts .claude/rules/api.md
   ```

   打ったら、テンプレートの検証3「touch を打ったか」に記録します。

2. **ターミナル:** `claude`
3. **Claude に入力:** 「Read ツールで api/sample.ts を読んで、何をする関数か一文で教えてください」
   - **見る:** `Loaded .claude/rules/api.md` の行が出たか、返事の最初に【API】があるか → 記録【3A】
4. **Claude に入力:** 「Read ツールで files/small1.txt から files/small6.txt までの6つを読んで、それぞれの合言葉を答えてください」
5. **Claude に入力:** `/compact`
   - 要約が終わるまで待ちます。「要約するほどの会話がない」と出たら、1〜2往復話してから打ち直します。
6. **見る:** `Compacted` の行の下に並ぶ行を、そのまま貼る → 記録【3B】
7. **Claude に入力:** 「ファイルを読まずに答えてください。さっきの関数の名前は何でしたか」
   - **見る:** 返事の最初に【API】があるか → 記録【3C】
8. **Claude に入力:** 「Read ツールで api/sample.ts をもう一度読んで、引数の数を答えてください」
   - **見る:** `Loaded .claude/rules/api.md` の行が出たか、返事の最初に【API】があるか → 記録【3D】
   - ファイルを読まずに答えた場合（`Read 1 file` などの表示が出ない場合）は、「Read ツールで読み直してください」と言い直します。
9. **Claude に入力:** `/exit`

**予想**

- 【3A】Loaded の行あり・【API】あり
- 【3B】`Read files/small1.txt` 〜 `Read files/small5.txt` の5行。`api/sample.ts` と `.claude/rules/api.md` は出てこない
- 【3C】【API】なし
- 【3D】Loaded の行あり・【API】あり

<details>
<summary>予想と違ったとき・なぜそうなるか</summary>

- **【3B】に `.claude/rules/api.md` が出た:** ルールのファイルが戻っています。手順1の `touch` を打ったか確かめてください。
- **【3C】で【API】が付いた:** 要約の文章にルールが書き残された可能性があります。`ctrl+o` で要約の全文を開き、【API】のルールが書かれているか見て、テンプレートに書いてください。

</details>

## 検証4　要約の直後に動くフックは、本当に動くか

**ねらい:** `.claude/settings.json` に、要約の直後だけ「検証用の合言葉は いちょう です。」と Claude に伝えるフックがあります。要約の前は知らず、要約のあとは知っているかを見ます。

1. **ターミナル:** `claude`
2. **Claude に入力:** 「ファイルを読まずに答えてください。検証用の合言葉を知っていますか。知らなければ『知らない』と答えてください」
   - **見る:** 答え → 記録【4A】
3. **Claude に入力:** `/compact`
   - 要約が終わるまで待ちます。「要約するほどの会話がない」と出たら、1〜2往復話してから打ち直します。
4. **Claude に入力:** 「ファイルを読まずに答えてください。検証用の合言葉を知っていますか。知らなければ『知らない』と答えてください」（2と同じ文）
   - **見る:** 答え → 記録【4B】
5. **Claude に入力:** `/exit`
   - 手順以外に Claude がファイルを読んでいたら、テンプレートに記録します。

**予想**

- 【4A】知らない
- 【4B】いちょう

<details>
<summary>予想と違ったとき・なぜそうなるか</summary>

- **【4A】で「いちょう」と答えた:** Claude が README や `.claude/settings.json` を読んだか、前に検証したときの合言葉が auto memory（Claude が自動で残すメモ）に保存されています。Claude Code の中で `/memory` を打ち、開いたメモから合言葉の行を消して保存してから、やり直してください。
- **【4B】も「知らない」:** 会社の設定でプロジェクトのフックが禁止されている可能性があります。テンプレートに「フック禁止かも」と書いてください。

</details>

## 終わったら

1. 予想と違った点を、テンプレートの「気づいたこと」に書きます。
2. 誰かに見せる前に、**社内のフォルダ名やプロジェクト名、ユーザー名、PC 名が混ざっていないか**確認してください。
3. **ターミナル:** 次を打つと元の状態に戻ります（`touch` で変えた更新日時は戻りませんが、検証には影響しません）。

   ```bash
   git restore .
   git status   # 「nothing to commit, working tree clean」と出れば元どおり
   ```
