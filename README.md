# Claude Code コンパクション検証キット

会話が長くなると、Claude Code は古いやり取りを要約に置き換えます（コンパクション）。このキットでは、要約のあとに何が残り、何が消えるのかを、公式ドキュメントの記述どおりか手元で確かめます。

- 参照ドキュメント: https://code.claude.com/docs/en/context-window#what-survives-compaction
- 所要時間: 20分ほど（4つの検証。それぞれ新しいセッションで行います）
- 必要なもの: Claude Code、git、ターミナル（macOS または Linux）
- 少しですがトークンを使います

## 確かめること

| 検証 | 確かめること |
|---|---|
| 1 | プロジェクト直下の CLAUDE.md は、要約のあとファイルから読み直されるか |
| 2 | 読んだファイルは要約のあと、更新日時の新しい順に5つまで戻るか。大きいファイルは名前だけになるか |
| 3 | `paths:` 付きのルールは要約で消え、対象ファイルを触ると戻るか |
| 4 | `compact` 用の SessionStart フックは、要約のあとに実行されるか |

## 準備

```bash
git clone https://github.com/cookkawasaki/claude-compact-check
cd claude-compact-check
claude --version
```

- `claude --version` の出力を、結果テンプレート（`result-template.txt`）に書き写してください。
- モデルは Sonnet を勧めます（`/model` で切り替え）。安く、「★ を付ける」のような指示にもきちんと従うためです。エフォート（考える量）の設定があれば、低め〜標準で十分です。使ったモデルはテンプレートに書いてください。
- 初めて `claude` を起動すると、このフォルダを信頼するか聞かれます。許可してください（検証4のフックを動かすため）。
- 個人の `~/.claude/CLAUDE.md` や、会社共通の Claude Code 設定があれば、テンプレートの「手元の設定」に書いてください（中身は書かなくて構いません）。結果に影響することがあるためです。

## 共通の約束

- **検証ごとに Claude Code を起動し直してください。** 終わったら `/exit` で閉じ、次の検証は `claude` から始めます。前の検証の内容が混ざらないようにするためです。
- 「 」の中の文は、そのまま入力してください。
- `/compact` を打って「要約するほどの会話がない」という趣旨の表示が出たら、適当にもう1〜2往復話してから打ち直してください。
- すべて終わったら、次のコマンドで元の状態に戻せます。

```bash
git restore .
git status   # 「nothing to commit, working tree clean」と出れば元どおり
```

## 検証1　CLAUDE.md は要約のあと読み直されるか

このフォルダの `CLAUDE.md` には「返事の最後の行に ★ を書く」とあります。途中でこれを ◆ に書き換え、要約の前後でどちらが付くかを見ます。

1. `claude` を起動し、「自己紹介を一文でしてください」と入力します。返事の最後に ★ が付くか確かめます。
   - 付かない場合は、個人の設定などが邪魔している可能性があります。テンプレートにそう書き、検証1はここで終えてください。
2. **Claude Code は開いたまま**、別のターミナルを開き、同じフォルダで次を実行します（エディタで ★ を ◆ に書き換えても構いません）。

   ```bash
   perl -pi -e 's/★/◆/g' CLAUDE.md
   ```

3. Claude Code に戻り、「好きな季節を一文で教えてください」と入力します。返事の最後の記号を記録します（要約前）。
4. `/compact` を入力し、要約が終わるのを待ちます。
5. 「好きな果物を一文で教えてください」と入力します。返事の最後の記号を記録します（要約後）。
6. 「ファイルを読まずに答えてください。いまの CLAUDE.md は、返事の最後の行にどの記号を書くよう指示していますか」と入力し、答えを記録します。
7. `/exit` で閉じ、`git restore CLAUDE.md` で元に戻します。

**予想:** 要約前は ★、要約後は ◆。6 の答えも ◆。

- 要約の文章の中に「★ を付ける」という指示が書き残されることがあります。5 で ★ が出ても、6 で ◆ と答えれば、CLAUDE.md は読み直されています。
要約前の時点で既に ◆ なら、その版の Claude Code は要約を待たずに CLAUDE.md を読み直しています。それも大事な結果なので、そのまま記録してください。

## 検証2　読んだファイルは更新日時の新しい順に5つまで戻るか

`files/` には、小さいファイル6つ（`small1.txt`〜`small6.txt`）と、大きいファイル1つ（`big.txt`、約1万トークン）があります。

ドキュメントには「更新日時（ファイルが最後に変更された日時）の新しいものから5つ」とあります。そこで、**読ませる順番と、更新日時の順番をわざと逆にします。** どちらの順で選ばれたかが、結果から分かります。

1. `claude` を起動する**前に**、次のコマンドでファイルの更新日時をそろえます（small1 がいちばん新しく、small6 がいちばん古くなります）。

   ```bash
   touch -t 202601010106 files/small1.txt
   touch -t 202601010105 files/small2.txt
   touch -t 202601010104 files/small3.txt
   touch -t 202601010103 files/small4.txt
   touch -t 202601010102 files/big.txt
   touch -t 202601010101 files/small5.txt
   touch -t 202601010100 files/small6.txt
   ```

2. `claude` を起動し、「files/small1.txt と files/small2.txt を読んで、それぞれの合言葉を答えてください」
3. 「files/small3.txt から files/small6.txt までの4つを読んで、それぞれの合言葉を答えてください」
4. 「Read ツールで files/big.txt を最初から最後まで読んで、最初の行と最後の行を答えてください」
5. `/compact` を入力し、要約が終わるのを待ちます。
6. 要約の直後に表示される、`Read ...` と `Referenced file ...` の行に出てくるファイル名をすべて書き写します。
7. 参考として、「ファイルを読まずに答えてください。いま中身が分かるファイルと、名前しか分からないファイルを挙げてください」と入力し、答えを記録します。
8. `/exit` で閉じます。

**予想（ドキュメントどおりなら）:** `Referenced file` には `files/big.txt`。`Read` には small1〜small4 の4つ。small5 と small6 は出てこない。

- もし `Read` が small3〜small6 になったら、更新日時ではなく「読んだ順」で選ばれています。ドキュメントと違う結果なので、ぜひ記録してください。
- Claude が `head` や `tail` などのコマンドで big.txt を見た場合は、Read ツールで読んだことにならず、結果が変わります。そのときはテンプレートに書いてください。

- 手順2〜4以外のファイル（README など）を Claude が自分から読んだ場合は、それも数に入ります。テンプレートに書いてください。
- 6の行が画面に出ない場合は「表示なし」と書き、7の答えだけ記録してください。

## 検証3　`paths:` 付きのルールは要約で消え、また戻るか

`.claude/rules/api.md` には、`api/` のファイルを触るときだけ読み込まれるルール「返事の最初に【API】と書く」があります。

1. `claude` を起動します。
2. 「api/sample.ts を読んで、何をする関数か一文で教えてください」と入力します。返事の最初に【API】があるか記録します。
3. `/compact` を入力し、要約が終わるのを待ちます。
4. 「ファイルを読まずに答えてください。さっきの関数の名前は何でしたか」と入力します。【API】があるか記録します。
5. 「api/sample.ts をもう一度読んで、引数の数を答えてください」と入力します。【API】があるか記録します。
6. `/exit` で閉じます。

**予想:** 2 はあり、4 はなし、5 はあり。

- ルールが読み込まれると、ターミナルに `Loaded .claude/rules/api.md` という行が出ます。2 のあと、`/compact` の直後、5 のあと の3か所で、この行が出たかどうかも記録してください。
- 4 で【API】が付いた場合は、要約の中にルールが書き込まれたか、要約のあとに `api/sample.ts` が自動で読み直され、それと一緒にルールも戻った可能性があります。どちらか分からなくて構いません。見えたとおり記録してください。

## 検証4　`compact` 用の SessionStart フックは、要約のあとに動くか

`.claude/settings.json` に、要約の直後だけ「検証用の合言葉は いちょう です。」と Claude に伝えるフックがあります。

1. `claude` を起動します。
2. 「ファイルを読まずに答えてください。検証用の合言葉を知っていますか。知らなければ『知らない』と答えてください」と入力し、答えを記録します。
3. `/compact` を入力し、要約が終わるのを待ちます。
4. 2と同じ文を入力し、答えを記録します。
5. `/exit` で閉じます。

**予想:** 2 は「知らない」、4 は「いちょう」。

- 合言葉はこの README と `.claude/settings.json` にも書いてあります。Claude がどこかのファイルを読んでから答えた場合は、テンプレートに書いてください。
- 検証をやり直すときは、`/memory` で auto memory に合言葉が保存されていないか確かめてください。保存されていると、要約前から「いちょう」と答えてしまいます。
- 会社の設定でプロジェクトのフックが禁止されていると、4 も「知らない」になります。その場合は「フック禁止かも」と書いてください。

## 結果の送り方

1. `result-template.txt` の中身をコピーし、空欄を埋めます。
2. 依頼者に Slack の DM で送ってください。
3. 送る前に、**社内のフォルダ名やプロジェクト名、ユーザー名、PC 名が混ざっていないか**確認してください。OS 欄は「macOS 15」程度で十分です。
